# Build Your Own X catalog map

The upstream [Build Your Own X](https://github.com/codecrafters-io/build-your-own-x) README describes itself as a compilation of step-by-step guides for recreating technologies. Its categories are an idea index, not a guarantee that every linked tutorial remains available or accurate.

## Topic families

The catalog currently groups material around:

- **Graphics and simulation:** 3D renderers, physics engines, voxel engines, visual recognition, augmented reality.
- **AI and computation:** AI models, neural networks, processors, programming languages, regex engines.
- **Data and distributed systems:** databases, search engines, blockchain/cryptocurrency, BitTorrent clients, distributed systems.
- **Operating environments:** operating systems, shells, network stacks, Docker/container concepts, emulators and virtual machines, web browsers, web servers.
- **Developer tools and interfaces:** command-line tools, Git, text editors, front-end frameworks/libraries, bots, games, template engines.
- **Other and uncategorized:** additional projects that do not fit the principal headings.

The list is broad and evolves. Recheck the upstream README when selecting a topic rather than treating this snapshot as exhaustive.

## Turning an idea into a portfolio project

1. Choose one topic and identify the core idea that can be demonstrated without reproducing an entire production system.
2. Compare a few candidate tutorials for clarity, recency, runnable examples, and links to primary references.
3. Define one observable learning outcome. Prefer a small complete loop over a long feature checklist.
4. Verify behavior against primary sources when the demo touches a standard, protocol, or security-sensitive mechanism.
5. Build an independent implementation, preserve attribution, and state the simplifications.

## Reference selection checklist

- Does the link resolve, and is the content actually a guided implementation?
- Does the author define the intended scope and prerequisites?
- Are code and claims explained, or is this only a finished repository?
- Are correctness-sensitive details supported by a specification or official docs?
- Are dependencies and tools suitable for a local portfolio demo?
- Can the project be safely run with bounded, sanitized inputs and no private credentials?
